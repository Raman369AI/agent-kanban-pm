How to run multiple coding agents in parallel

Running two or three coding agents at once is easy. Keeping them from overwriting each other, and knowing what each one did afterwards, is the hard part. This is the workflow that works.

1. Split the work into independent cards

Each card should touch a separable area and state its acceptance criteria. Overlapping cards are the main cause of merge pain, so sequence them with dependencies instead of running them together.

2. Give every agent its own workspace

Agents sharing one checkout will clobber each other's files. Run each in its own Git worktree; Agent Kanban PM supports worktree isolation and uses explicit leases so two workers cannot claim the same task.

3. Assign by role, not by habit

kanban agents discover
kanban roles list
kanban roles assign worker claude --mode headless
kanban run

Choose an agent per role. You might use one CLI for implementation and another for review.

4. Watch progress in one place

The board streams each session's terminal output and shows card state. kanban sheet gives a compact status from the terminal.

5. Gate on review

Treat "in review" as a checkpoint, not a claim of completion. Check the diff, tests and agent output on the card, then approve, return or recover. Use kanban handoff status --workspace . to inspect a worktree.

6. Audit afterwards

kanban audit --auto --commands lists unsupervised runs and the commands they recorded, useful when you let agents run with approvals off.
